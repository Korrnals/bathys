## [0.12.0] — 2026-09-14

Тема: «Deep Verdicts» — Фаза 3 library_docs + source_check. Командный релиз: два системных инженера параллельно (брифы и ревью — Tech Lead).

### Добавлено

- **`source_check(claim, urls?)` — 6-й MCP-инструмент**: детерминированная проверка утверждения без LLM (механика разобрана у pi-web-access и переведена на нашу архитектуру). Источники → параллельные нырки под `query=claim` → пассажи с `passage_id` и sha256-хэшами → вердикт `SUPPORTED/CONTRADICTED/UNCLEAR/MISSING-EVIDENCE` с confidence; полярные маркеры RU+EN с проверкой негации; классы источников (official_docs/forum/news/blog/repo_issue, RU-форумы). **Наше усиление против эталона**: домен-независимость — вердикт с одного домена капится на 0.65 с пометкой (правило двух независимых источников).
- **Фаза 3 `library_docs`**: (а) `version` — пин версий через GitHub-теги (`raw.githubusercontent.com/{owner}/{repo}/{tag}/README.md` с перебором `v`-префиксов; док-сайты — честная пометка «последняя»); (б) **авторастущий пользовательский индекс** `BATHYS_DOCS_INDEX` (~/.local/share/bathys/docs-index.json): успешные search-резолвы запоминаются, повторный вызов той же библиотеки идёт мгновенно со статусом `user-index`; приоритет seed → user-index → search; атомарная запись, идемпотентность.
- Тесты: +51 (159 OK): 28 source_check (полярность/негация/термин-фильтр/независимость/полный конвейер на фейках) + 21 library_docs Фаза 3 + config.
- Контракты: секции `library_docs` (фазы 1–3) и `source_check` в `mcp-tools.md`, футеры в `output-format.md`; env `BATHYS_DOCS_INDEX` в таблицах.

## [0.9.0] — 2026-09-09

Тема: «Borrowed Ideas» — три фичи, заимствованные из pi-web-access (реализация наша; разведка самого источника проведена живьём через Bathys).

### Добавлено

- **`find` в `read_url`** — точный поиск по кэшу сырца без сети (заимствовано из `get_search_content`/`findText`): счётчики совпадений, позиции и контекст; live: 25 совпадений «self-attention» по кэшу PDF за 0.0 с. Работает и по PDF-кэшу.
- **PDF text-layer в HTTP-ярусе** (`pymupdf`, локально, без ML/облака; заимствовано из их PDF-обработки): PDF-URL читается первым ярусом, `content-type: application/pdf` → текст → обычная дистилляция. Live: «Attention Is All You Need» (2.2 МБ) → 1489 симв. под запрос за 1.1 с. Сканы без текстового слоя — честный отказ (OCR-инициатива остаётся paused); отдельные PDF-ошибки не эскалируют в браузер (`_FinalTierError`) — браузер на PDF всё равно падает с «Download is starting».
- **Типизация fallback-причин F-102** (заимствовано из их `fallbackOn`): captcha/suspended весят ×3 (липкое состояние), timeout ×1, прочее ×2 — капчевые движки исключаются из fallback-наборов быстрее.

### Исправлено

- JS-shell-детектор больше не срабатывает на PDF/извлечённых страницах (пустой raw-html по дизайну ≠ оболочка) — ранее это маскировало PDF-результат ошибкой браузера.

## [0.7.0] — 2026-09-08

Тема: «Ship & Setup» — двухъярусное извлечение без обязательного браузера и модульная установка.

### Добавлено

- **Двухъярусное извлечение** (`crawler.py`): по умолчанию страницы читает собственный HTTP-движок (httpx, миллисекунды, ноль браузера); headless-Chromium включается автоматически только когда страница — JS-оболочка (детект: app-root-разметка, пустое тело, экранирование контента) или HTTP-ярус не смог. Замеры: Wikipedia 0.61 c, GitHub 1.0 c по HTTP против ~4–5 c с браузером. `BATHYS_BROWSER=off|auto|always` управляет режимом; браузер больше не обязательная зависимость запуска — `bathys setup` ставит его для JS-страниц, но сервер работает и без него.
- **`bathys setup`** — полная установка одним вызовом: браузерный движок (пропускается по `--skip-browser`) → интеграция всех найденных харнессов → субагент → итоговые подсказки. Идемпотентен; после `pip install bathys` пользователю достаточно `bathys setup`.
- **Точечная установка `bathys install <HARNESS>`**: `bathys install hermes` пишет только Hermes, отсутствующий конфиг целевого харнесса создаётся с нуля (проверено: opencode-конфиг создан в его формате); `--list` печатает все таргеты с их путями и статусом; неизвестное имя — понятная ошибка.

### Изменено

- README: идентичность переписана («самостоятельный продукт, а не обёртка над чужими сервисами: реализует весь конвейер сам»); основной путь установки — `pip install bathys` + `bathys setup`, альтернативы (npm, исходники, минимальные образы) и ручное подключение убраны под `<details>`-каты.
- Синтаксис вызова диспетчера: `bathys` (сервер) / `bathys setup` / `bathys install [targets]` / `bathys doctor`; справка `--help` обновлена.

## [0.2.0] — 2026-09-06

Тема релиза: «Качество выдачи» (см. `docs/product/roadmap.md`). Приёмка: 19/20 запросов ≥ 3 хитов.

### Добавлено

- **F-101** Устойчивость к пустой выдаче и капчам: пустой/заблокированный outcome ретраится с независимыми наборами движков и нарастающими паузами (1.5s×n); пустой результат кэшируется коротким TTL (10 мин), чтобы «сломанная минута» не закрывала час retries.
- **F-102** Здоровье движков: парсинг `unresponsive_engines` из SearXNG, счётчик подряд молчащих (порог 3), `Engine.bad_engines()` для диагностики; плохие движки исключаются из fallback-наборов.
- **F-106** `secs` в футерах `read_url` и HIT-`web_search` — SLO `p95(read)` и HIT-латентность измеримы из футеров.
- **F-202** Параметр `refresh` во всех трёх инструментах: игнорирует кэш на чтение (перезаписывает его).
- **F-301** (ранний перенос из v0.4) Вежливый клиентский режим: `BATHYS_SEARCH_MIN_INTERVAL` (дефолт 1.0 c) между поисками; `BATHYS_DIVE_CONCURRENCY` (дефолт 4) вместо хардкода семафора.
- **F-302** Пин SearXNG: нативный режим чекаутится на полный SHA-коммит (`SEARXNG_REF`/`BATHYS_SEARXNG_REF`, маркер `.bathys-ref` без лишней сети); compose-образ — датированный тег `2026.9.5-c7f3080aa` с того же коммита (апстрим git-тегов не имеет).
- **F-201** (ранний перенос из v0.3) Пакетное чтение `read_urls(urls, query?, total_chars=12000, refresh?)`: 1–10 URL одним вызовом, дедупликация, общий бюджет с перераспределением на успешные, per-URL секции ошибок; футер `batch N urls · ok/n ok · …`.
- **F-401** (юнит-часть, ранний перенос из v1.0) 49 юнит-тестов без сети (`tests/`, stdlib unittest, ~0.05 c): distill/cache/searx/config целиком + мок-тесты ретраев F-101, веживости F-301 и здоровья движков F-102. Прогон: `.venv/bin/python -m unittest discover -s tests`.
- Новые env: `BATHYS_SEARCH_MIN_INTERVAL`, `BATHYS_SEARCH_RETRIES` (0–3), `BATHYS_DIVE_CONCURRENCY` (1–8), `BATHYS_SEARXNG_REF`.

### Изменено
