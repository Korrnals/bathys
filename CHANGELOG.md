Формат: Keep a Changelog; версии — semver. Дата — дата выпуска версии.

## [0.7.1] — 2026-09-08

### Добавлено

- **Однострочный установщик `install.sh`** — основной путь установки: `curl -fsSL https://raw.githubusercontent.com/Korrnals/bathys/main/install.sh | bash`. Приватный venv в `~/.local/share/bathys/venv` (решение против хрупкости `pip --user` между контейнерами и PEP 668), бутстрап pip через `get-pip.py` для минимальных образов, PATH прописывается в `.profile`/`.bashrc`, затем `bathys setup` и финальный `bathys-doctor`. Идемпотентен (повтор = обновление), без sudo, ничего вне `$HOME`. Живые прогоны: двойной (создание + идемпотентное обновление), setup прописал zcode+hermes с бэкапами, doctor 5/6 (бэкенд поднимается при первом вызове — норма).
- README: однострочник — основной путь Quick start; `pip install` + `bathys setup` — равноправная альтернатива «без скрипта»; npm/исходники — под катом.

## [0.7.0] — 2026-09-08

Тема: «Ship & Setup» — двухъярусное извлечение без обязательного браузера и модульная установка.

### Добавлено

- **Двухъярусное извлечение** (`crawler.py`): по умолчанию страницы читает собственный HTTP-движок (httpx, миллисекунды, ноль браузера); headless-Chromium включается автоматически только когда страница — JS-оболочка (детект: app-root-разметка, пустое тело, экранирование контента) или HTTP-ярус не смог. Замеры: Wikipedia 0.61 c, GitHub 1.0 c по HTTP против ~4–5 c с браузером. `BATHYS_BROWSER=off|auto|always` управляет режимом; браузер больше не обязательная зависимость запуска — `bathys setup` ставит его для JS-страниц, но сервер работает и без него.
- **`bathys setup`** — полная установка одним вызовом: браузерный движок (пропускается по `--skip-browser`) → интеграция всех найденных харнессов → субагент → итоговые подсказки. Идемпотентен; после `pip install bathys` пользователю достаточно `bathys setup`.
- **Точечная установка `bathys install <HARNESS>`**: `bathys install hermes` пишет только Hermes, отсутствующий конфиг целевого харнесса создаётся с нуля (проверено: opencode-конфиг создан в его формате); `--list` печатает все таргеты с их путями и статусом; неизвестное имя — понятная ошибка.

### Изменено

- README: идентичность переписана («самостоятельный продукт, а не обёртка над чужими сервисами: реализует весь конвейер сам»); основной путь установки — `pip install bathys` + `bathys setup`, альтернативы (npm, исходники, минимальные образы) и ручное подключение убраны под `<details>`-каты.
- Синтаксис вызова диспетчера: `bathys` (сервер) / `bathys setup` / `bathys install [targets]` / `bathys doctor`; справка `--help` обновлена.

## [0.6.2] — 2026-09-08

Публикационная волна: PyPI + NPM + кастомные интеграции.

### Добавлено

Публикуется на NPM как `bathys-mcp`.
- **Живые интеграции на машине мейнтейнера**: Hermes — `config.yaml` + субагент установлены идемпотентно.

### Изменено

- **Метаданные пакета** (PyPI-витрина): `description` переведён на канон продукта («Unified local deep-research search service…», вместо обёрточной формулировки про SearXNG/Crawl4AI); добавлены `keywords` (mcp, deep-research, local-first…), `classifiers`, секция `[project.urls]` (Homepage/Repository/Changelog/Documentation).

## [0.6.1] — 2026-09-08

Расширение автодетекта `bathys install` на базовый набор харнессов (форматы подтверждены первоисточниками каждого клиента).

### Добавлено

- **Новые таргеты инсталлера**: VS Code-семейство — Cline / Roo Code / Kilo Code (`mcp_settings.json` в globalStorage, записи cline-формата), Gemini CLI (`~/.gemini/settings.json` → `mcpServers`), Windsurf (`~/.codeium/windsurf/mcp_config.json`), Zed (`~/.config/zed/settings.json` → `context_servers`; файл создаётся, если каталог есть), opencode (`~/.config/opencode/opencode.json` → `mcp` c `command`-массивом), goose (`~/.config/goose/config.yaml` → `extensions`, stdio-поля `cmd/args/envs`), Hermes (`~/.hermes/config.yaml` → `mcp_servers`).
- **YAML-контур без зависимостей**: идемпотентные правки `extensions`/`mcp_servers` с сохранением остального документа байт-в-байт (append/insert/replace покрыты тестами).
- `--print-config` печатает блоки для каждого харнесса в его собственном формате (вложенность `mcp.servers` для zcode, YAML для goose/hermes); Pi (badlogic pi-mono) честно маршрутизируется на дроп-ин — MCP-конфига у него нет.
- `install()` принимает `_targets` (инъекция реестра для тестов).

### Изменено

- Тест-хелпер `set_targets` подменяет все три источника реестра (базовый, cline-семья, YAML-семья); `print-config`-тест использует полный фикстурный набор. Сьют: 102 OK.

## [0.6.0] — 2026-09-08

Тема: «Native Install» — нативная автоматическая интеграция в харнессы одним вызовом.

### Добавлено

- **`bathys install`** — установщик интеграции: автодетект харнессов по стандартным путям (`~/.zcode/cli/config.json`, `~/.claude.json`, `~/.cursor/mcp.json`, `~/Library/Application Support/Claude/claude_desktop_config.json`), идемпотентная запись сервера `bathys` (бэкап конфига с таймстампом перед записью; повторный запуск не трогает актуальное), `--with-agent` — копирование субагента `bathys-researcher`, `--searxng-home` — запись env, `--dry-run`, `--print-config` (готовые блоки для ручного подключения). Битые/недоступные конфиги пропускаются с пометкой, не ломая установку.
- **CLI-диспетчер точки входа `bathys`**: без аргументов — MCP-сервер (stdio); `install` / `doctor` — подкоманды; `--help` — справка. Отдельная точка входа `bathys-install` сохранена.
- Документация: install.md — шаг 5 «Подключение автоматически» + таблица базовых директорий (`~/.local/share/bathys`, `~/.cache/bathys`); README — блок «Автоматически/Вручную» в подключении; cases.md — шаг C-1 через `bathys install`.

## [0.5.0] — 2026-09-07

Тема: «Identity & Harness» — репозиционирование продукта и нативная интеграция в харнессы.

### Изменено (позиционирование)

- **Канон идентичности**: Bathys — единый локальный поисковый сервис глубокого ресёрча для ИИ-агентов, не «обёртка над SearXNG+Crawl4AI»: продукт владеет стратегией (что искать/читать/сколько вернуть) и собственным конвейером; SearXNG и Crawl4AI — внутренние сменные движки (аналогия: БД не «обёртка над B-tree»). Переписаны: README (первый экран, «Движки и собственный слой»), `docs/product/charter.md` (миссия, принципы: «продукт владеет стратегией, движки сменные» + отдельный «без LLM внутри»), `docs/product/competitive.md`, вводные `docs/index.md` и docstring сервера; ADR-0006 получил примечание об истории «трёх инструментов».
- **Публикационная гигиена**: документация обезличена для репозитория (пути окружения → плейсхолдеры, «владелец» → «мейнтейнер», среда разработки убрана в troubleshooting; 20 файлов, ноль личных вхождений); README переработан в компактную профессиональную структуру (SVG-баннер, quick start, подключение харнессов, карта документации, страница живых кейсов). Имя `bathys` свободно на PyPI и NPM (пакет не переименовывается); репозиторий — `github.com/Korrnals/bathys`.

### Добавлено (нативная интеграция в харнессы)

- **MCP instructions-playbook** (193 слова, RU): сервер сам объясняет харнессу матрицу выбора инструментов, правила итераций, семантику сигналов — без правки инструкций харнесса.
- **Tool annotations** на всех 4 инструментах (`title`, `readOnlyHint`, `openWorldHint`) — проверено живым stdio-клиентом, что реально доставляются.
- **3 MCP-промпта-стратегии**: `bathys_deep_research(question, time_range?)`, `bathys_source_audit(claim, urls)`, `bathys_fresh_scan(topic, window?)` — рендерятся харнессом как готовые планы.
- **Раздел `docs/integrations/`**: `overview.md` + гайды `zcode.md`, `claude-code.md`, `cursor.md`, `generic-mcp.md` (конфиги, установка субагента, дроп-ин).
- **`agents/HARNESS-DROPIN.md`** — канонический блок для файла инструкций харнесса (AGENTS.md / CLAUDE.md / .cursor/rules).

### Добавлено (встроенный агент-специалист)

- **`agents/bathys-researcher.md`** — субагент глубокого ресёрча, заточенный под Bathys: метод 1–3 итераций, верификация двумя независимыми источниками, семантика сигналов (`robots-refused`, `(not fetched — …)`, футеры), бюджетная дисциплина. Исполняется вызывающим харнессом — без LLM внутри Bathys (принцип хартии сохранён).
- **Скиллы `bathys-deep-dive` и `bathys-source-audit`** (`agents/skills/`) — процедуры глубокого исследования и аудита источников.
- **Аудит и переработка агент-слоя специалистом-архитектором агентов (GCW)** после первичной авторки: исправлен критичный **инвертированный сигнал кэша** в инструкциях четырёх объектов (refresh нужен при `cache HIT` с устаревшими данными; `MISS` уже свежий — прежняя формулировка подталкивала сжигать refresh впустую); выровнен диапазон `read_urls` (1–10) в пяти местах; `time_range` дополнен `year`; description-триггеры переписаны по принципу «когда звать + когда не звать»; `instructions=` дополнен сигналами `No results … tried N engine sets` и `Answer:`; бюджеты и семантика футеров (HIT/MISS/MIX) сведены в матрицу согласованности шести объектов без противоречий. Верификация: 72 теста OK, stdio EXIT=0.

## [0.4.0] — 2026-09-06

Тема: «Эксплуатация» (+ v0.3.0 «Паритет с Tavily» поставлены одной итерацией). Оба критерия приёмки закрыты, кроме двух наблюдательных (недельная/двухнедельная доля пустых/капч — ждут живого окна владельца).

### Добавлено (v0.4)

- **F-303** robots.txt: прямые нырки страниц уважают robots.txt хоста (fail-open на недоступном/404; поиск не затрагивается — движки SearXNG читают сами). Отказ — не ошибка: футер `robots-refused` + пометка в теле, отказ кэшируется на час. Live-проверка: LinkedIn (`Disallow: /`) корректно отказан. Дефолт — уважение, `BATHYS_ROBOTS=0` отключает.
- **F-304** Локальный журнал `~/.local/share/bathys/metrics.jsonl`: одно JSON-событие на вызов (tool, cache HIT/MISS/MIX, chars_in/out, secs, ok, error_class, url_hash/q_hash — sha256-префиксы без хранения адресов); события ошибок, включая спец-класс `robots`. Агрегатор `scripts/metrics_report.py` (hit-rate, медианное сжатие, p50/p95, ошибки, накопленный tokens_saved). `BATHYS_METRICS=0` отключает.
- **F-305** `bathys-doctor` (console script): диагностика стека одним запуском — бэкенд-пинг, сверка пина SHA, кэш-статистика, журнал метрик, crawl4ai-импорт, `--full` — запуск headless-chromium. Exit-код для скриптов.

### Добавлено (v0.3)

- **F-204** JSON-режим `web_search(as_json=true)`: чистый JSON `{query, count, hits[], answer?}` без футера — для машинных потребителей; телеметрия уходит в `metrics.jsonl`.
- **F-203** API-движки одним ключом: `BATHYS_ENGINE_BRAVE_KEY` включает движок `brave` в генерируемых настройках нативного SearXNG (`services.render_settings`); live-проверка с реальным ключом — за владельцем.

### Зависимости/упаковка

- `bathys-doctor` в `[project.scripts]`; `__version__` синхронизирован с pyproject.

## [0.2.0] — 2026-09-06

Тема релиза: «Качество выдачи» (см. `docs/product/roadmap.md`). Приёмка: 19/20 запросов ≥ 3 хитов.

### Добавлено

- **F-101** Устойчивость к пустой выдаче и капчам: пустой/заблокированный outcome ретраится с независимыми наборами движков и нарастающими паузами (1.5s×n); пустой результат кэшируется коротким TTL (10 мин), чтобы «сломанная минута» не закрывала час retries.
- **F-102** Здоровье движков: парсинг `unresponsive_engines` из SearXNG, счётчик подряд молчащих (порог 3), `Engine.bad_engines()` для диагностики; плохие движки исключаются из fallback-наборов.
- **F-106** `secs` в футерах `read_url` и HIT-`web_search` — SLO `p95(read)` и HIT-латентность измеримы из футеров.
- **F-202** Параметр `refresh` во всех трёх инструментах: игнорирует кэш на чтение (перезаписывает его).
- **F-301** (ранний перенос из v0.4) Вежливый клиентский режим: `BATHYS_SEARCH_MIN_INTERVAL` (дефолт 1.0 c) между поисками; `BATHYS_DIVE_CONCURRENCY` (дефолт 4) вместо хардкода семафора.
- **F-302** Пин SearXNG: нативный режим чекаутится на полный SHA-коммит (`SEARXNG_REF`/`BATHYS_SEARXNG_REF`, маркер `.bathys-ref` без лишней сети); compose-образ — датированный тег `2026.9.5-c7f3080aa` с того же коммита (апстрим git-тегов не имеет).
- **F-201** (ранний перенос из v0.3) Пакетное чтение `read_urls(urls, query?, total_chars=12000, refresh?)`: 1–10 URL одним вызовом, дедупликация, общий бюджет с перераспределением на успешные, per-URL секции ошибок; футер `batch N urls · ok/n ok · …`.
- **F-401** (юнит-часть, ранний перенос из v1.0) 49 юнит-тестов без сети (`tests/`, stdlib unittest, ~0.05 c): distill/cache/searx/config целиком + мок-тесты ретраев F-101, веживости F-301 и здоровья движков F-102. Прогон: `.venv/bin/python -m unittest discover -s tests`.
- Новые env: `BATHYS_SEARCH_MIN_INTERVAL`, `BATHYS_SEARCH_RETRIES` (0–3), `BATHYS_DIVE_CONCURRENCY` (1–8), `BATHYS_SEARXNG_REF`.

### Изменено

- **F-105** **BREAKING (объявлено заранее, K1):** футеры переведены на единую символьную шкалу `ch` — устранён дефект `_tok` (символы под видом токенов, приукрашивание сжатия ~4×). Реальное сжатие `read_url` ≈ 7.3×. Контракты `output-format.md` и регекспы `metrics.md` §3.1 обновлены синхронно.
- Тело пустой выдачи может расширяться суффиксами `· tried N engine sets · unresponsive: …` (префикс `No results for:` неизменен).

### Исправлено

- Wiki-страницы: `PruningContentFilter`-мусор заголовков Medium-статей — без изменений в этом релизе (known issue, v0.3).
