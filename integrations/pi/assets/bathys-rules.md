## Веб-доступ: всегда через Bathys (локальный поисковый сервис, MCP)

Вся работа в интернете — поиск, чтение страниц, исследования — идёт через
инструменты MCP-сервера Bathys, когда он подключён в среде запуска. Сторонние
web-инструменты не использовать: у Bathys свои дистилляция под запрос,
токен-бюджеты, кэш и метрики.

Выбор инструмента:

- Исследовательский вопрос («что/как/почему/сравни») → `deep_research(query)` —
  ищет, читает топ-источники и возвращает дистиллят под запрос одним вызовом.
- Нужен только пул ссылок → `web_search(query)`.
- Один известный URL → `read_url(url, query=…)`; 2–10 URL →
  `read_urls(urls, query=…)` (общий бюджет, битая страница стоит строку).
- Свежесть: `time_range` = day|week|month|year; протухший кэш (`cache HIT` с
  устаревшими данными) — один `refresh=true` на главный источник.

Правила работы:

1. Формулируй `query` как вопрос: дистиллятор отбирает пассажи по смыслу.
   Максимум 3 итерации без сдвига — смени угол (термины из найденного, язык).
2. Ключевой факт — два независимых источника (разные домены); конфликт
   источников фиксируй явно с обеими URL.
3. Каждый нетривиальный факт в ответе сопровождай URL из секций Bathys.
4. Сигналы: `(not fetched — …)` — источник не прочитан, используй остальные;
   `robots-refused` — сайт запретил чтение, уважай; `No results … tried N
   engine sets` — смени формулировку. Футер `[bathys: …]` — статистика,
   не для цитирования.

Готовые стратегии (MCP-промпты Bathys): `bathys_deep_research`,
`bathys_source_audit`, `bathys_fresh_scan` — бери как стартовый шаблон плана.
