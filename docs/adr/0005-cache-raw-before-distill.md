# ADR 0005 — Кэшировать очищенный сырец ДО дистилляции

| Поле | Значение |
|---|---|
| Статус | Accepted |
| Дата | 2026-09-06 |
| Применимо к | Bathys v0.1.0 |
| Затрагивает | `src/bathys/cache.py`, `src/bathys/core.py` |

## Context

Дорогая часть пайплайна — не дистилляция (микросекунды на чистом Python), а сеть и рендер: метапоиск, загрузка, подъём chromium-страницы. Повторные вызовы — норма для агентного цикла: модель перечитывает тот же URL с другим `query`, тот же запрос уходит повторно. Значит, кэшировать надо так, чтобы повторный вопрос не стоил ни байта сети.

## Decision

SQLite TTL-кэш (`{CACHE_DIR}/cache.db`, таблица `cache(k PRIMARY KEY, exp REAL, v TEXT)`, JSON-значение, индекс по `exp`) хранит **очищенный markdown до дистилляции**:

| Что | Ключ | TTL (дефолт) | Содержимое |
|---|---|---|---|
| Поиск | `("search", query, max_results, category, engines, language, time_range)` | `search_ttl` = 3600 | полный outcome: hits, answers, suggestions, seconds, raw_chars |
| Страница | `("page", url)` | `page_ttl` = 86400 | `url, status, title, text` (очищенный markdown), `raw_chars` |
| Ошибка fetch | `("page", url)` | `max(3600, page_ttl//24)` = 3600 | `{"error": "Класс: сообщение"}` — переигрывается как `RuntimeError` |

Следствия дизайна: ключ страницы не содержит `query` — пере-чтение с другим запросом даёт `cache HIT` и пере-дистилляцию из сырца; у crawl4ai выставлен `CacheMode.BYPASS` — двойного кэша нет; истёкшие записи лениво игнорируются на чтении, фоновой чистки нет.

## Alternatives

| Альтернатива | Почему отклонена |
|---|---|
| Без кэша | повторные вызовы агента снова платят сетью и рендером — главный сценарий экономии теряется |
| Кэш дистиллята | привязывает запись к паре (url, query, бюджет); бесплатная пере-дистилляция под новый запрос пропадает |
| Redis | операционный груз (демон, конфиг, мониторинг) ради кэша одного процесса; SQLite достаточно |

## Consequences

- Положительные: повторный `read_url` с иным `query` мгновенен и бесплатен; исходники страниц переживают рестарт агента (TTL 24 ч); отказ URL кэшируется — шторм повторных таймаутов гасится.
- Отрицательные: данные устаревают в пределах TTL (свежесть приносится в жертву экономии); раздутая БД не ужимается автоматически — чистка ленивая, ручная — удалить файл `cache.db`; ошибки fetch «запоминаются» на час — retry раньше TTL невозможен без смены URL.

## Источники

`src/bathys/cache.py`; `src/bathys/core.py` (`_search_outcome`, `_read`); `src/bathys/crawler.py` (`CacheMode.BYPASS`).
