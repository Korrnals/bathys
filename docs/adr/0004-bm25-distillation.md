# ADR 0004 — BM25-дистилляция под запрос вместо выдачи «как есть»

| Поле | Значение |
|---|---|
| Статус | Accepted |
| Дата | 2026-09-06 |
| Применимо к | Bathys v0.1.0 |
| Затрагивает | `src/bathys/distill.py`, `src/bathys/crawler.py`, `src/bathys/core.py` |

## Context

Скачанная страница — это 50–300k символов, из которых под вопрос обычно отвечают единицы процентов. Bathys продаёт экономию токенов модели, поэтому «отдать всё и пусть модель читает» — прямое противоречие продукту. При этом сервер принципиально не содержит LLM: отбор контента должен быть детерминированным, локальным и мгновенным.

## Decision

Пять стадий очистки; на выходе пассажи, уложенные точно в символьный бюджет:

```mermaid
flowchart LR
    R[рендер headless] --> T[excluded tags/selector<br/>word_count_threshold=8]
    T --> P["PruningContentFilter<br/>threshold=0.48 → fit_markdown"]
    P --> S[slim_markdown:<br/>ссылки → метки, минус ref-строки]
    S --> B["BM25-пассажи под запрос<br/>жёсткий бюджет символов"]
```

1. **Рендер** — headless-браузер Crawl4AI (см. [ADR 0001](0001-python-crawl4ai.md)).
2. **Структурная резка** — `excluded_tags`/`excluded_selector` (nav, footer, aside, `.ads`, …), `word_count_threshold=8`.
3. **PruningContentFilter 0.48** — отсечение неосновного контента, `fit_markdown`.
4. **`slim_markdown`** — inline-ссылки/картинки схлопываются в текст метки, markdown ref-строки удаляются, пустые строки сжимаются.
5. **`passages(text, query, max_chars)`** — чанки ~320 символов (жёсткий предел 500, разрыв >900); BM25-flavoured скоринг: `tf·(1+ln tf)·ln(1+N/df)` с частотами терминов запроса; стоп-слова RU+EN; отбор в порядке документа до исчерпания бюджета; фолбэк — lead-абзац при отсутствии query или нулевом пересечении терминов.

Результат детерминирован: тот же сырец + тот же запрос + тот же бюджет = тот же текст. `read_url` с новым запросом по кэшированному сырцу пере-дистиллируется бесплатно (см. [ADR 0005](0005-cache-raw-before-distill.md)).

## Alternatives

| Альтернатива | Почему отклонена |
|---|---|
| Отдавать `fit_markdown` целиком | сжигает токены: сотни тысяч символов вместо тысяч — противоречит продукту |
| Локальные embedding-реранкинг | тяжело (модель на борту) и медленно; отложено с явным триггером (деградация качества отбора) |
| LLM-суммаризация | нарушает принцип «слой данных»: Bathys без LLM, недетерминированно и дорого |

## Consequences

- Положительные: сжатие в символьной шкале ≈ 7× на `read` (см. `docs/operations/metrics.md` §4) без сети и моделей; пере-дистилляция из кэша бесплатна.
- Отрицательные: эвристика — редкие форматы (таблицы, код) режутся чанкованием; параметр 0.48 подобран эмпирически и требует пересмотра при смене crawl4ai; `head-trimmed`-режим без query оставляет только начало документа.

## Источники

`src/bathys/distill.py`; `src/bathys/crawler.py` (`CrawlerRunConfig`); `src/bathys/core.py` (`_read`).
