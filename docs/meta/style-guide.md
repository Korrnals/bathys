# Стайлгайд документации Bathys

Правила для всех файлов в `docs/` и для `README.md`. Цель — чтобы документы читались как один почерк и не протухали.

## Язык

- Проза — по-русски; идентификаторы, пути, имена переменных и команд — английские в бэктиках: запуск `.venv/bin/bathys`, переменная `BATHYS_START_MODE`.
- Не смешивать языки внутри одного предложения; устоявшиеся технические термины (`headless`, `маркдаун` → писать `markdown`) оставлять как принято в среде.
- Терминология — только из [glossary.md](glossary.md); новый термин сначала попадает в глоссарий, потом в текст.

## Структура

- Один файл — одна тема; длинную инструкцию делить на файлы и связывать ссылками, а не растягивать в простыню.
- Заголовки без пропусков уровней: читатель, пробежавший только H2, должен понять форму документа.
- Абзац — одна мысль, 2–5 строк; последовательности и чек-листы — списками.
- Таблицы — для сравнений и соответствий; ячейки таблиц писать глагольными формами («возвращает ранжированный список», а не «ранжированный список ссылок»).

## Диаграммы

- В `docs/` потоки, состояния и связи рисовать **mermaid** — GitHub рендерит его из коробки; не воспроизводить диаграмму текстом, который труднее сканировать.
- ASCII-графика допустима только как декоративный элемент `README.md`.
- Под диаграммой — 2–4 пункта того, чего на ней не видно (тайминги, ветки ошибок, ограничения).

## Ссылки и нумерация

- Внутренние ссылки — относительные, от файла к файлу; перед завершением работы прогнать линк-чек (см. «Definition of done»).
- ADR именуются `NNNN-slug.md` с нулём-набивкой до четырёх цифр: `docs/adr/0001-native-searxng-mode.md`; путь к ADR в текстах пишется кодом, пока файл не создан.
- Чужие зоны (`docs/contracts/`, `docs/product/`) — ссылаться по путям, не редактировать.

## Факты и цифры

- Каждое число в документе либо взято из кода (указать модуль), либо из футеров и [metrics.md](../operations/metrics.md) — без «примерно на глаз».
- Известные отклонения и план их закрытия описывать только там, где им место: контракты и роадмап; не тащить продуктовые оговорки в пользовательские гайды.
- Секреты в примерах маскировать; `secret_key` локального SearXNG писать как `"bathys-local-…"`.

## Definition of done

Документ готов к мержу, когда:

- [ ] все перекрёстные ссылки живы (относительные пути разрешаются от файла);
- [ ] факты сверены с кодом: имена модулей, дефолты, границы параметров;
- [ ] термины совпадают с [glossary.md](glossary.md);
- [ ] mermaid-диаграммы рендерятся на GitHub (проверить превью PR);
- [ ] нет заглушек и `TODO`; недостающий кусок либо написан, либо явно запрошен у ответственного за документ.
