# Глоссарий Bathys

Термины, которыми говорит документация и футеры сервера. Правило стайлгайда: новый термин сначала сюда, потом в текст.

## Морская метафора

| Термин | Значение |
|---|---|
| Сонар | этап поиска: SearXNG-метапоиск по 70+ движкам находит «координаты» — ранжированный список ссылок. Реализует `searx.py`. |
| Нырёк (dive) | crawl одной страницы: headless-chromium рендерит её и вытаскивает полный текст. Считается в футере `deep_research` как `dove N pages`; реализует `crawler.py`. |
| Дистиллят | результат `distill.passages()`: пассажи страницы, отобранные BM25 под запрос, в порядке документа и в рамках бюджета символов. Единственное, что видит агент. |
| Bathys | имя проекта — от греч. βαθύς «глубокий» (батискаф): глубокий ресёрч без облака. |
| Батискаф | сам Bathys: сонар нашёл координаты — аппарат нырнул — на палубе только артефакты (дистилляты). |

## Механика

| Термин | Значение |
|---|---|
| Футер | строка `[bathys: …]` в конце каждого ответа: число хитов, `dove`, сжатие «сырьё → ответ» в символах, время, `cache HIT`/`MISS`. Первичный источник данных для [metrics.md](../operations/metrics.md). |
| HIT / MISS | попадание/промах кэша SQLite. HIT — ответ собран из `$BATHYS_CACHE_DIR/cache.db` без сети (повтор поиска или страницы); MISS — ходили в сеть и сохранили результат. |
| `MIX` | кэш-флаг пакета `read_urls` в событии `metrics.jsonl`: часть страниц пришла из кэша, часть — из сети (`HIT` — все из кэша, `MISS` — все из сети). В футер пакета не пишется. |
| `batch` / пакет | вызов `read_urls`: 1–10 известных URL одним запросом, дедупликация по нормализованному URL, общий бюджет `total_chars` (300–30000) с перераспределением долей на успешные страницы. Сбой страницы — секция одной строкой, не сорванный вызов. Футер: `batch N urls · ok/n ok · …`. |
| `as_json`-режим | `web_search(as_json=true)`: чистый JSON `{query, count, hits[], answer?}` без футера — для машинных потребителей (программа вместо LLM). Телеметрия вызова уходит в `metrics.jsonl` как обычно. |
| `robots-refused` | пометка в футере одиночного `read_url`: хост запретил этот путь краулерам в robots.txt. Отказ — не ошибка, кэшируется на час; поиск не затрагивается, недоступный robots.txt считается разрешением. Дефолт — уважение; `BATHYS_ROBOTS=0` отключает. В пакете `read_urls` тот же отказ — секция `(not fetched — …)`. |
| Native mode | режим автостарта, в котором SearXNG живёт в `$BATHYS_SEARXNG_HOME` (клон + venv) и запускается дочерним процессом `python -m searx.webapp` с логом в `searxng.log`. Для сред без docker; см. [configure.md](../getting-started/configure.md). |
| `fit_markdown` | выход контент-фильтра Crawl4AI: html, очищенный `PruningContentFilter` и приведённый к markdown. Именно он кэшируется как сырец страницы. |
| `PruningContentFilter` | контент-фильтр Crawl4AI на стадии 3 конвейера: оценивает плотность текста и выбрасывает бойлерплейт. Настройка Bathys — `threshold=0.48`, `threshold_type="fixed"`; см. [pipeline.md](../architecture/pipeline.md). |

## Эксплуатация

| Термин | Значение |
|---|---|
| `metrics.jsonl` | локальный журнал вызовов в `$BATHYS_DATA_DIR` (дефолт `~/.local/share/bathys/metrics.jsonl`): одно JSON-событие на вызов — tool, кэш-флаг, `chars_in/out`, `secs`, `ok`, `error_class`; адреса не хранятся, только sha256-префиксы `url_hash`/`q_hash`. Агрегатор — `scripts/metrics_report.py`; `BATHYS_METRICS=0` выключает журнал целиком. |
| `bathys-doctor` | console script диагностики стека одним запуском: конфиг, бэкенд-пинг, сверка пина SHA, кэш-статистика, журнал метрик, crawl4ai-импорт; `--full` — запуск headless-chromium. Exit-код `0`/`1` для скриптов; бэкенд сам не поднимает — FAIL по бэкенд-пингу при незапущенном сервере нормален. |

## Экономика

| Термин | Значение |
|---|---|
| QUOTA-экономия | главный экономический эффект: облачные MCP-инструменты поиска и чтения списывают ~1% месячной квоты подписки за вызов, а Bathys делает ту же работу локально — облачная квота не тратится вовсе. Исходная мотивация — в [charter.md](../product/charter.md). |
