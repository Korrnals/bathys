# Реестр функций Bathys

Сопутствующие документы: [charter.md](charter.md) · [roadmap.md](roadmap.md) · [competitive.md](competitive.md).

Приоритеты (используются во всём реестре и в роадмапе):

- **P0** — критично: без этой функции версия не выходит.
- **P1** — важно: входит в версию при наличии ёмкости.
- **P2** — позже: осознанно отложено за пределы ближайших версий.

Статус «поставлено» означает: функция работает end-to-end и подтверждена замером
или smoke-проверкой (`scripts/smoke.py`, `scripts/stdio_check.py`).

## Поставленные функции (v0.1)

| F-ID | Функция | Что делает | Где доказано |
|---|---|---|---|
| F-001 | Метапоиск SearXNG | Выполняет поиск через JSON API SearXNG: дедуплицирует хиты по домену и пути, вычищает трекинг-параметры (`utm_*`, `gclid`, `fbclid`), сортирует по score, фильтрует по `time_range`/`category`/`language`/`engines` | `src/bathys/searx.py`; замер 37k → 511 токенов |
| F-002 | Чтение страниц с JS-рендером | Рендерит страницу общим headless-Chromium (Crawl4AI), вырезает навигацию, футеры, рекламу и cookie-баннеры (`PruningContentFilter`, excluded-теги) и возвращает чистый Markdown | `src/bathys/crawler.py`; замер 17k → 581 токенов |
| F-003 | Дистилляция под запрос | Прогоняет текст через `slim_markdown` и BM25-отбор пассажей (RU/EN стоп-слова), сохраняет порядок документа и жёсткий бюджет символов; без запроса читает начальные пассажи (head-trim) | `src/bathys/distill.py` |
| F-004 | TTL-кэш SQLite | Кэширует выдачи поиска (TTL 3600 с) и сырые страницы (TTL 86400 с); пере-дистилляция той же страницы с другим запросом не качает сеть; ошибки страниц кэшируются примерно на час | `src/bathys/cache.py`, `src/bathys/core.py`; повторы 0,0 с |
| F-005 | Автостарт бэкенда в 3 режима | Поднимает SearXNG сам: внешний инстанс → docker/podman compose (или `BATHYS_START_CMD`) → нативный режим «клон + venv дочерним процессом» с get-pip fallback для минимальных образов; режим форсируется `BATHYS_START_MODE` | `src/bathys/services.py` |
| F-006 | Мгновенные ответы и подсказки | Поднимает SearXNG `answers`/`suggestions` наверх выдачи, чтобы агент часто не читал страницы вовсе | `src/bathys/core.py` |
| F-007 | Бюджеты и футеры-статистика | Зажимает бюджеты (`max_results` 1–20, `max_sources` 1–6, `per_source_chars` 300–8000, `max_chars` 300–50000) и добавляет в каждый ответ футер со сжатием, временем и cache HIT/MISS | `src/bathys/core.py`; замер `deep_research` 35k → 7k токенов за 3,2 с |
| F-008 | MCP-сервер из трёх инструментов | Публикует `deep_research`, `web_search`, `read_url` через FastMCP stdio, держит stdout чистым для протокола и инструктирует агента начинать ресёрч с `deep_research` | `src/bathys/server.py`; `scripts/stdio_check.py` |

## Поставленные функции (v0.2, 2026-09-06)

| F-ID | Функция | Что делает | Где доказано |
|---|---|---|---|
| F-105 | Честная шкала футеров | `_ch` печатает символы одной шкалой во всех футерах; устранён дефект `_tok` (символы под видом токенов, приукрашивание сжатия ~4×) | `src/bathys/core.py`; смок: `searx json 37549 ch → 1986 ch`, `page 17063 ch → 2325 ch` (реальные 7.3× против прежних «29×») |
| F-106 | `secs` в футерах | Добавлены секунды в футеры `read_url` и HIT-`web_search` — SLO `p95(read)` и HIT-латентность теперь измеримы из футеров | `src/bathys/core.py`; смок: `page … · cache HIT · 0.0s` |
| F-302 | Пин релиза SearXNG | Нативный режим пинится на полный SHA-коммит (`SEARXNG_REF`, env `BATHYS_SEARXNG_REF`, checkout по маркеру без лишней сети); compose-образ — датированный тег `2026.9.5-c7f3080aa`, собранный с того же коммита; апстрим git-тегов не имеет | `src/bathys/config.py`, `src/bathys/services.py::_ensure_ref`, `src/bathys/compose.yaml` |
| F-101 | Устойчивость к пустой выдаче и капчам | Пустой/заблокированный outcome ретраится с независимыми наборами движков и нарастающими паузами (1.5s×n, `BATHYS_SEARCH_RETRIES` 0–3); пустой результат кэшируется коротким TTL (10 мин) | `src/bathys/core.py::_search_outcome`; мок-тест в `tests/test_core.py`; live: приёмка 19/20 при лежавшем `startpage` |
| F-102 | Здоровье движков | Парсинг `unresponsive_engines`, счётчик подряд молчащих (порог 3), `Engine.bad_engines()`, исключение плохих из fallback-наборов | `src/bathys/searx.py`, `src/bathys/core.py::_record_health`; live: `startpage` пойман в приёмочном прогоне |
| F-202 | Принудительное обновление кэша | Параметр `refresh` во всех инструментах игнорирует кэш на чтение и перезаписывает его | `src/bathys/core.py`, `src/bathys/server.py` |
| F-201 | Пакетное извлечение `read_urls` | 1–10 URL одним вызовом: дедупликация по нормализованному URL, общий бюджет `total_chars` (300–30000) с перераспределением на успешные, per-URL секции ошибок, футер `batch N urls · ok/n ok` | `src/bathys/batch.py`, `src/bathys/server.py`; `scripts/batch_check.py`: 3 URL → `268371 ch → 1069 ch · 5.9s` |
| F-301 | Вежливый клиентский режим | `BATHYS_SEARCH_MIN_INTERVAL` (1.0 c) между поисками к бэкенду; `BATHYS_DIVE_CONCURRENCY` (1–8) вместо хардкода семафора нырков | `src/bathys/core.py::_polite_pace`; тест в `tests/test_core.py` |
| F-401 | Юнит- и smoke-тесты (юнит-часть) | 49 тестов без сети: distill (11), cache (5), searx (13), config (7), core с моками ретраев/веживости/здоровья (13); stdlib unittest, ~0.05 c | `tests/`; прогон `Ran 49 tests — OK` |
| F-203 | API-движки с ключами | `BATHYS_ENGINE_BRAVE_KEY` одним env включает движок `brave` в настройках нативного SearXNG (`render_settings`); хиты несут маркеры движков; docker — правка settings вручную | `src/bathys/services.py::render_settings`; структурная проверка (live с ключом — за мейнтейнером) |
| F-204 | Структурированный JSON-режим | `web_search(as_json=true)` — чистый JSON `{query, count, hits[], answer?}` без футера | `src/bathys/core.py`; live: json.loads проходит, 4 хита |
| F-303 | Уважение robots.txt | Прямые нырки сверяются с robots.txt хоста (fail-open при недоступности); отказ — пометка `robots-refused` + кэш отказа, не ошибка вызова | `src/bathys/core.py::_robots_allowed`; live: LinkedIn отказан, Wikipedia прочитана |
| F-304 | Локальный журнал вызовов | `metrics.jsonl` по схеме metrics.md §3.2 (hashes без адресов, error_class, cache MIX для пакетов) + агрегатор `scripts/metrics_report.py` | `src/bathys/core.py::_log_metrics`, `src/bathys/batch.py`; live: события пишутся |
| F-305 | Диагностика `bathys-doctor` | Console script: бэкенд-пинг, сверка пина SHA, кэш, журнал метрик, crawl4ai, `--full` chromium | `src/bathys/doctor.py`; live: 5/6 (бэкенд поднят только при живом Engine — хинт напечатан) |

### v0.4 «Эксплуатация»

| F-ID | Функция | Приоритет | Что делает | Обоснование |
|---|---|---|---|---|
| F-301 | Вежливый клиентский режим | P0 | Вводит задержки с джиттером между запросами к одному поисковику и ограничивает параллельные нырки конфигом | Гигиена клиента снижает частоту капч; это не обход блокировок, а уважение к источникам |
| F-303 | Уважение robots.txt | P1 | Проверяет robots.txt перед краулингом и возвращает пометку отказа вместо контента запрещённых путей | Этика и юридическая гигиена; дефолт политики — отдельное решение (см. хартию, «Открытые решения») |
| F-304 | Локальный журнал вызовов | P1 | Пишет локальный журнал (режим бэкенда, cache HIT, сжатие, ошибки) и агрегирует его в метрики из `docs/operations/metrics.md` | Критерии успеха хартии нельзя проверить без данных |
| F-305 | Диагностика `bathys doctor` | P2 | Добавляет команду, которая проверяет бэкенд, кэш, браузер и печатает отчёт | Сокращает время диагностики «а почему у меня пусто» |
