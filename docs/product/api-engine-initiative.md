# Инициатива: API-движок метапоиска для Bathys (F-203+)

| Поле | Значение |
|---|---|
| Статус | Утверждена владельцем 2026-09-09 («поддерживаю!»); материалы собраны живым е2е через Bathys (deep_research + read_urls по docs.searxng.org) |
| Мотивация | Капчи Google/Startpage на скрейп-движках — экзистенциальный риск (хартия); API-движки = легальный, безкапчевый запасной путь (исследование это подтверждает: публичные инстанцы гибнут от общих IP-банов, self-host лечится лимитами + API) |
| Принцип | Strictly опционально: ноль ключей по умолчанию, ноль облака без явного согласия владельца (хартия) |

## Архитектурное решение (ключевое!)

**Bathys НЕ пишет свой движок для SearXNG.** Разведка показала: у SearXNG **уже есть готовые API-движки** — `braveapi` (`use_official_api: true`, `api_key`), `exaapi` (search engine for AI agents!), Kagi, Jina — они лежат в апстриме и активируются одним ключом в settings.yml. Наша задача — не новый код, а **оркестрация**: рендер ключей в генерируемые настройки (механизм `render_settings` уже существует с v0.3 для Brave) + приоритизация API-движков в fallback-цепочке F-101.

Собственный движок (`bing_api`, см. обсуждение #5651: «никто не сделал API-based Bing») — **только если** подтверждённый спрос после Brave/Exa.

## Роадмап

### Фаза A — «Brave + Exa из коробки» (1 вечер, без нового движка)

1. Расширить `services.render_settings`: `BATHYS_ENGINE_BRAVE_KEY` (уже есть) + `BATHYS_ENGINE_EXA_KEY` → секции engines в генерируемом settings.yml нативного режима (формат из docs.searxng.org/dev/engines/online/exaapi.html: `name/engine/shortcut/api_key/inactive: false`).
2. `_RETRY_ENGINE_SETS` (F-101): при наличии API-ключей — первый fallback-набор строится из API-движков (`braveapi,exaapi,duckduckgo`), скрейп-движки уходят в хвост.
3. `bathys-doctor`: строка «API-движки: brave [вкл], exa [выкл]».
4. Доки: configure.md (два ключа), runbook.md (таблица API vs скрейп).

**Критерии приёмки:** с `BATHYS_ENGINE_EXA_KEY` поиск работает при полностью лежащих Google/Bing (инжект их отказа моком); без ключей — поведение нулевое (не трогаем ничего).

### Фаза B — «Умный fallback» (1 вечер)

1. F-102 (здоровье движков): API-движки получают иммунитет-вес — при 3+ фейлах скрейп-движков поиск автоматически смещается на API-набор.
2. Метрики: `metrics.jsonl` пишет `engine_set` (api|scrape|mixed) — видим долю спасённых запросов.
3. Инструкции-playbook сервера: строка «при No results → предложи владельцу API-ключ».

**Критерии:** инжект 5 подряд капч на скрейп → выдача приходит с API; метрика отражает.

### Фаза C — «Собственный API-движок» (только по триггеру)

Триггер: владелец подтверждает реальную боль (Brave/Exa не покрывают RU-язык или тариф) или просит Bing API (free-tier 1000/мес, из #5651).
Работа: engine-модуль по канону апстрима (about-дикт, request(), response()) → PR в SearXNG (даём в апстрим, не форк!) + зеркальная поддержка в Bathys до мержа.

## Чеклист работ (Фаза A, первый заход)

- [ ] `render_settings`: блок exaapi по ключу (формат сверен с docs.searxng.org).
- [ ] `render_settings`: секция engines не дублируется при обоих ключах (один блок engines).
- [ ] `_RETRY_ENGINE_SETS`: динамический первый набор из доступных API-движков.
- [ ] Тесты: render с 0/1/2 ключами; retry-план с/без ключей.
- [ ] doctor: отображение статуса API-движков.
- [ ] Доки: configure.md, runbook.md, CHANGELOG.
- [ ] Живой тест: с твоим Brave-ключом (если дашь) или без ключей (нулевой след).

## Риски и границы

| Риск | Ответ |
|---|---|
| Облачная зависимость? | Только по явному ключу владельца; дефолт — ноль облака (хартия не нарушена) |
| Тарифы? | Brave free 2000/мес, Exa — AI-agent тариф; фиксируем в доках, не в коде |
| Расползание на «свой поисковый индекс»? | Нет: это оркестрация fallback, не индекс (Not-doing хартии) |
