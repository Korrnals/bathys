# Интеграция с харнессами — обзор

Bathys — stdio MCP-сервер: харнесс запускает его как дочерний процесс и на
рукопожатии получает не только четыре инструмента, но и playbook их выбора.
Эта страница — единая точка входа: выберите харнесс, скопируйте конфиг,
при желании доставьте субагента-специалиста.

## Подключение: сначала автоматика

```bash
bathys setup             # полный стек: браузер → все найденные харнессы → субагент
bathys install           # автодетект + прописывание (то же без браузерного шага)
bathys install hermes zcode   # точечно; отсутствующие конфиги целевых таргетов создаются
bathys install --list    # карта всех таргетов с путями и статусом
```

Интеграция идемпотентна, перед записью создаёт бэкап с таймстампом,
повторный запуск не трогает актуальное. Таргеты (14): zcode, claude-code,
claude-desktop, cursor, cline, roo-code, kilo-code, gemini-cli, windsurf,
zed, opencode, goose, hermes + pi (у Pi нет MCP-конфига — дроп-ин в
`AGENTS.md`). Ручное подключение всегда доступно: `bathys install
--print-config` печатает блоки под схему каждого клиента; снять — `bathys
uninstall [HARNESS…]` (семантика — [runbook.md](../operations/runbook.md),
«Снятие Bathys»).

## Харнессы

| Харнесс | Куда кладём конфиг | Инструкция |
|---|---|---|
| zcode | блок `mcpServers` в конфиге MCP-серверов | [zcode.md](zcode.md) |
| Claude Code | `.mcp.json` в корне проекта | [claude-code.md](claude-code.md) |
| Claude Desktop | `claude_desktop_config.json` | [claude-code.md](claude-code.md) |
| Cursor | `~/.cursor/mcp.json` или проектный `.cursor/mcp.json` | [cursor.md](cursor.md) |
| Любой другой MCP-клиент | конфиг stdio-сервера вашего клиента | [generic-mcp.md](generic-mcp.md) |

Конфиг везде одинаков по форме — блок `mcpServers` с командой запуска `bathys`;
отличается только файл. Базовый вариант с разбором `BATHYS_SEARXNG_HOME` и
примеры диалогов — в [getting-started/integrate.md](../getting-started/integrate.md).

## Матрица выбора инструментов

То же правило, которое сервер сообщает харнессу в instructions-playbook:

| Ситуация | Инструмент | Почему |
|---|---|---|
| Исследовательский вопрос («что/как/почему/сравни») | `deep_research(query)` | ищет, читает топ-источники и возвращает дистиллят под запрос одним вызовом |
| Нужен только пул ссылок | `web_search(query)` | ранжированные хиты со сниппетами, без содержимого страниц |
| Результат нужен программе, а не человеку | `web_search(query, as_json=true)` | чистый JSON `{query, count, hits[], answer?}` без футера |
| Один известный URL | `read_url(url, query=…)` | чтение одной страницы; `query` оставляет только релевантные пассажи |
| 2–10 известных URL | `read_urls(urls, query=…)` | пакет с общим бюджетом; битая страница стоит строку, не вызов |

Свежесть — `time_range` (`day`/`week`/`month`/`year`); подозрение протухшего
кэша — `refresh=true` (дорого, не по умолчанию). Полные сигнатуры и диапазоны
параметров — в [mcp-tools.md](../contracts/mcp-tools.md).

## Что даёт нативная интеграция

Из коробки, без правок системного промпта, харнесс получает четыре вещи
(источник — `src/bathys/server.py`):

1. **MCP instructions-playbook.** На рукопожатии `initialize` сервер отдаёт
   `instructions`: матрицу выбора инструментов, правила работы (запрос — вопрос,
   максимум 3 итерации без сдвига, два независимых источника на ключевой факт)
   и семантику сигналов (`not fetched`, `robots-refused`, футеры). Клиенты,
   которые показывают instructions, отдают playbook модели автоматически.
2. **Annotations инструментов.** Каждый инструмент объявлен с человекочитаемым
   `title` и хинтами `readOnlyHint` / `openWorldHint` — клиент может показать
   названия и пометить инструменты как безопасные для автозапуска.
3. **Три стратегии-промпта.** `bathys_deep_research` (глубокая проработка одного
   вопроса за 1–3 итерации), `bathys_source_audit` (аудит утверждения по списку
   URL), `bathys_fresh_scan` (свежий срез по теме за окно времени) — готовые
   шаблоны плана, которые клиент рендерит как обычные MCP-промпты.
4. **Субагент-специалист и скиллы.** [agents/bathys-researcher.md](../../agents/bathys-researcher.md) —
   профиль агента глубокого ресёрча через Bathys, исполняется вызывающим
   харнессом (своей LLM в Bathys нет); скиллы [bathys-deep-dive](../../agents/skills/bathys-deep-dive/SKILL.md)
   и [bathys-source-audit](../../agents/skills/bathys-source-audit/SKILL.md) —
   процедурные сценарии «когда применять / процедура / выход». Команды установки —
   на страницах конкретных харнессов.

## Дроп-ин для файла инструкций

Нужен, если харнесс **не показывает** MCP instructions в контексте модели
(не все клиенты рендерят это поле) или если вы хотите жёстче закрепить правило
«весь веб-доступ — только через Bathys». Канонический блок — в
[agents/HARNESS-DROPIN.md](../../agents/HARNESS-DROPIN.md): он самодостаточен,
после вставки агент выбирает инструменты Bathys нативно и не ходит в интернет
мимо них.

Куда вставлять: zcode — `AGENTS.md`; Claude Code — `CLAUDE.md`; Cursor —
`.cursor/rules/*.mdc`; прочие клиенты — системный промпт. Хостится блок в одном
месте (репозиторий, `agents/`), страницы харнессов на него ссылаются.
