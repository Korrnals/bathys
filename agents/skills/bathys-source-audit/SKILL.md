# Bathys Source Audit — аудит источников и утверждений

## Когда применять

- Есть список ссылок и нужно проверить, что они действительно говорят то,
  что заявлено.
- Нужно проверить одно утверждение: «X правда, потому что <URL>».
- Нужна актуальность: «это ещё так в текущих версиях?»

## Процедура

1. **Пакетное чтение.** `read_urls(urls, query=…)` — в `query` спорный тезис
   словами: дистилляция вплотную к проверяемому утверждению, а не «вообще о
   чём статья». До 10 URL одним вызовом; битые отвалятся строкой
   `(not fetched — …)` — это не провал.
2. **Контекст источника.** Для каждого URL: домен/автор, дата (`published`
   в хитах поиска или дата в дистилляте), первоисточник или пересказ.
3. **Кросс-проверка.** Спорный тезис → `deep_research` с запросом вида
   «X критика / X опровержение / X alternatives»: ищи расхождения, а не
   подтверждения; при споре об актуальности добавь `time_range`.
4. **Свежесть.** Проверка «как сейчас» — один `refresh=true` на главный
   источник (повод: `cache HIT` при устаревших данных), не на весь пакет.
5. **Вердикт по каждому пункту**: подтверждено (≥2 независимых домена) /
   частично (1 источник) / опровергнуто (опровержение с URL) / непроверяемо
   (`robots-refused`, 404 — указать причину).

## Выход

Таблица «тезис → вердикт → источники (URL)» + абзац общего вывода. Каждый
вердикт содержит хотя бы один URL либо явную причину его отсутствия.

## Анти-паттерны

- Читать URL «вообще» без `query` — дистиллят размоется, проверка станет
  «похоже на правду».
- Считать два пересказа одного пресс-релиза независимыми источниками.
- Обходить `robots-refused`: фиксируй отказ и ищи другой первоисточник.
