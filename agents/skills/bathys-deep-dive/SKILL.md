# Bathys Deep Dive — глубокое исследование одного вопроса

## Когда применять

- Вопрос требует понимания, а не факта: «почему X», «как устроен Y», «что
  выбрать между Z и W»; ответ ляжет в решение (выбор библиотеки, диагноз,
  оценка рисков).
- Не для: проверка готовых URL или утверждения — скилл `bathys-source-audit`;
  свежий срез по теме — промпт `bathys_fresh_scan`; просто список ссылок —
  `web_search`.

## Процедура

1. **Заход.** `deep_research(query, max_sources=3)` с запросом-вопросом.
   Без предварительного `web_search`: первый заход уже ищет и читает
   топ-источники.
2. **Разбор дистиллята.** Из секций `## i.` выпиши: (a) что отвечает на
   вопрос, (b) что противоречит, (c) каких данных не хватает.
3. **Вторая итерация.** Переформулируй запрос терминами из (a)–(c) —
   терминами предметной области, найденными в источниках, не своими
   синонимами. Не хватает конкретики: `web_search` по узкому термину →
   `read_urls` по 2–4 лучшим URL с `query=…`. Максимум 3 итерации на
   формулировку, дальше — смена угла, не шестой заход.
4. **Свежесть.** Обзоры версий/цен/событий: `time_range="month"` (новости —
   `day`; допустимо `day`/`week`/`month`/`year`). `refresh=true` — только
   при протухшем кэше (`cache HIT`, а данные устарели), один раз на главный
   источник.
5. **Верификация.** Ключевые утверждения — 2 независимых домена; один
   источник — «по данным одного источника»; конфликт — показать обе версии
   с URL.
6. **Синтез.** Вывод первым предложением; далее 3–7 пунктов, у каждого
   нетривиального факта — URL; в конце «что не удалось проверить».

## Выход

- Вердикт/ответ + аргументация с URL у каждого нетривиального факта.
- Абзац «ограничения вывода»: возраст данных, единственные источники,
  непроверенные пункты.

## Анти-паттерны

- Пересказ дистиллята целиком — это сырьё, не ответ.
- Больше 3 итераций без смены угла.
- `Answer:` из выдачи как проверенный факт без подтверждения источником.
